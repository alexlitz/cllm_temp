### Key conclusions

1. **The var cluster baseline did NOT recover** despite `f4f9103d` and
   `f91cc6e0`. var_simple / var_mul / var_three / var_update remain
   0/25 each. The L3 `mem_byte_0_default` counter-write did not
   eliminate the final-output divergence. This may indicate the L14
   counter-op fires correctly but its sign/strength is insufficient
   to reverse the residual at the final emit position, OR the failure
   has migrated downstream again (recall memory note
   `project_var_failure_mode_shifted.md` — this cluster's failure
   block has shifted L17 → L34 → L13 → L3 → L34 in successive
   sessions).
2. **The if_eq / if_gt cluster recovery is durable** — 25/25 each at
   ID range 350-424. The `4273e968` EQ/NE recovery fix landed since
   the baseline.
3. **The 16-bit ALU cascade (mul/div/mod) shows mass regression in
   spec_k=128 mode.** Not measured at spec_k=0 in this run, but the
   delta vs 4683bbbc baseline is too large to be only a methodology
   artifact — the `bz-bnz` fix in `6eaa6ef6` and the BZ/BNZ override
   removal chain (`763ff75c` → `6eaa6ef6`) may have unmasked a
   step-1 carry-path divergence. **Re-measure at spec_k=0 to
   confirm before any fix attempt.**
4. **loop / recursion measurement requires lower batch size or
   spec_k=0.** OOM at 8 GiB allocations on 24 GiB A5000 indicates
   the speculative KV cache scales poorly with max_steps=451+. The
   prior triage doc flagged this as a known unmeasurable surface.

## Methodology caveats and next steps

1. **spec_k mismatch with baseline**: re-run shards 0, 137 at
   `C4_SPEC_K=0 C4_BATCH_USE_KV_CACHE=0` for an apples-to-apples
   comparison with `4683bbbc`. Wall time per shard ~2x but
   numerically comparable.
2. **Recursion measurement infeasible under current memory
   footprint**: shard 685 (recursion 685..821) sat 1100 s on a
   single max_steps=8369 batch. The fast shard runner needs a
   `C4_BATCH_CHUNK=4` override or eviction policy tuning for
   max_steps>500.
3. **Per-failure block attribution not collected** in this run
   (`C4_1096_TRACE_FAILURES=0` for throughput). Block-by-block
   probes per `VAR_REAL_ATTRIBUTION_2026_06_05.md` remain valid for
   the var cluster; the mul/div/mod regression needs its own
   block decomposition before fix proposals.
