## Current open blockers — 5 runtime-correctness clusters

These are the active gaps as of 2026-06-03 start. Single-rule fixes are
zero-sum (see `feedback_single_rule_fixes_are_zero_sum.md`). Use cluster agents
with verifier output, not manual diagnosis.

### Blocker 1: AX-write break (1096 lookup baseline = ~11%, smoke 12/39 efficient)

**Root cause identified:** `OPCODE_BYTE_LO.*.-1` cross-step rename in
`l5_ops.py:527`. A Phase 8.A / 9.B SSA pass renamed an opcode-byte-low read in a
way that broke step-1 dataflow — the renamed dim is unwritten on the first step,
so AX-write paths read zero and downstream ALU output is corrupted.

**Baseline:** 1096 lookup-mode = 11% pass (5 distinct failure clusters
identified, see blockers 2-5). Smoke = 12 pass / 39 fail. Note: 11% is the
real declarations-only baseline per `project_1096_sentinel_baseline.md` — the
2026-06-02 doc reported 0/137 but that was env-flag dependent.

**Status:** Fix in flight. The cluster agent is targeting the cross-step
rename directly, not the symptom.

### Blocker 2: L17.post_ops[0] block=27 "expected-token-never-wins" mass

58 of 384 1096 failures cluster here. Margin is uniformly -16.00 (suspiciously
quantized). OUT_HI[0] = +9.4e6 — runaway high-bit on the chosen-token logit.
Cluster agent in flight.

### Blocker 3: edge_pow2 sign-extension (2^3 = -24)

`pow2` tests producing negative results that look like sign-extension of an
intermediate byte (3-bit `0b011` read as `0b11111011`). Cluster agent in flight.

### Blocker 4: if_eq equality branch collapse

`if_eq` always takes one branch regardless of operand values. Cluster agent in
flight.

### Blocker 5: absdiff halt-horizon miss

`absdiff` runs past the expected halt step in some prefixes. Cluster agent in
flight.

## Cross-step rename anti-pattern class

The OPCODE_BYTE_LO break (blocker 1) is one instance of a broader pattern:
Phase 8.A / 9.B SSA renames sometimes broke step-1 dataflow because the new
name has no writer at step 0 (the previous name's writer was the implicit
zero-step seed). A corpus-wide audit of cross-step SSA renames against
step-0 producer coverage is **in flight** — when blocker 1 lands, expect the
same audit to surface 1-3 sibling cases.
