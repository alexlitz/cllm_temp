## (a) Attention bake-glue collapse — `_l10_bake_attn_heads`

Four `make_layer10_*_bake_op` closures each repeated the **same bake preamble**:

```python
proxy = _as_setdim_proxy(dim_positions)
attn = block.attn
head_allocator = _allocate_layer10_attention_heads()
attn._l10_head_allocator = head_allocator
HD = attn.W_q.shape[0] // attn.num_heads
Primitives.generate_attention_head(attn, <spec>(proxy, S), HD)   # ×N
# optional: attn.alibi_slopes.data[<slot>] = 1.0
```

The only per-op DATA is the list of head-spec factories and an optional alibi
slot. Extracted into a shared helper
`_l10_bake_attn_heads(block, dim_positions, S, specs, *, alibi_slot=None)`
(l10_ops.py, right after the existing `_bake_r_frame_passthrough_head` INCR-1
helper). Each bake closure is now a thin data-driven call:

| bake op | heads | alibi | call |
|---|---|---|---|
| `layer10_carry_relay_bake` | 1 | — | `_l10_bake_attn_heads(..., [carry_relay_spec])` |
| `layer10_psh_stack0_passthrough_bake` | 1 | — | `_l10_bake_attn_heads(..., [psh_stack0_spec])` |
| `layer10_psh_ax_broadcast_bake` | 3 (byte_h 1/2/3) | — | `_l10_bake_attn_heads(..., [ax_broadcast_spec(h) …])` |
| `layer10_stack0_byte_relay_bake` | 3 (4/5/6) | slot 6 | `_l10_bake_attn_heads(..., [relay, nonbitwise, persistence], alibi_slot=6)` |

The emitted `generate_attention_head` weights + the single `alibi_slopes` write
are byte-identical (golden `1c04c3fd` unchanged). This mirrors the prior INCR-1
collapse pattern that already unified the AX/SP/BP/PC R-FRAME passthrough bakes
(`_bake_r_frame_passthrough_head` / `_make_r_frame_passthrough_bake_op`) — those
were already done and left untouched.

**LOC**: l10_ops.py `+68 / −59` = net **+9 raw**, but the +68 includes the
~35-line shared helper (docstring included) now serving 4 call sites; ~40 lines
of duplicated bake preamble were removed. Per the documented "parameterizing ==
loop verbosity" reality (memory `project_core_loc_reduction_reality`), the win
is **single-source-of-truth** for the L10 attn bake preamble, not raw shrink.

## (b) CMP-combine — NOT byte-identically collapsible now (finding)

The two L10 cmp-combine banks are **already collapsed** to the single shared
`_derived_cmp_combine_rules` generator (task #446, `C4_DERIVE_CMP`): the
former per-op hand-enumeration + its `_cmp_default` / `_cmp_override_2way` /
`_cmp_override_3way` helpers were proven byte-identical and DELETED, so the
derivation is already the sole source.

The remaining ~145 LOC is the TWO parallel call sites:

* `_l10_comparison_combine_rules` — decode-row bank
  (`opcode_gate="OP_{op}"`, default_threshold 1.5, override3 2.5,
  `override_include_blocker=True`, MARK_PC blocker on overrides).
* `_layer10_alu_cmp_combine_rules` — L10-main ALU lane
  (`opcode_gate="SE_OP_{op}+0"`, default_threshold 2.5, override3 4.0,
  `override_include_blocker=False`, no MARK_PC blocker on overrides).

These have **genuinely different structural constants** (gate spelling,
thresholds, blocker inclusion) and produce different weights — merging them into
one bank is the **DERIVE_CMP / CMP-collapse P5-flip**, which is a SEMANTIC change
(one bank feeds a different residual read than the other), **not** a
byte-identical refactor. **Nothing here is byte-identically collapsible now.**
The ~145 LOC delete is deferred to the P5-flip and is out of scope for this
byte-identical pass.
