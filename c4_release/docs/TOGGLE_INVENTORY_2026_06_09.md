# c4_release Toggle Inventory (2026-06-09)

End-to-end audit of every `C4_*` / `NEURAL_VM_*` environment toggle that
materially affects the compiled VM, the batched / serial runners, the test
suite, or the on-disk cache. Generated by grepping `os.environ.get(...)` /
`os.environ.setdefault(...)` / `monkeypatch.setenv(...)` across the
`c4_release/` tree.

Status legend for the "Effect-tested" column:
- `yes` — at least one pytest exercises the toggle and asserts that flipping
  it changes observable behavior (forward, layout, IR, cache, return value).
- `parse` — only the parser / default value is unit-tested; no
  flip-vs-baseline check.
- `no` — no pytest asserts the toggle has effect.
- `added` — toggle was untested before this audit; this audit added a
  minimal effect-flip test (see `tests/test_toggle_inventory_audit.py`).

## Notes / mismatches vs the audit brief

- The brief lists `C4_TIMING`. The actual codebase has **no** `C4_TIMING`
  toggle. The two timing-print toggles are `C4_SMOKE_TIMING` and
  `C4_1096_TIMING` (and `tools/observe_backbone_contributions.py` has its
  own private prints).
- The brief lists "Declarations-only flags (per memory note)". These are
  `C4_DECLARATIONS_ONLY_BAKE` and `C4_REQUIRE_DECLARATIVE_BAKE`. Both
  documented and tested.
- The brief lists "Dim liveness flag: default-on" → `C4_DIM_LIVENESS=1`
  default. Confirmed in `layer_compiler.py:85`.
- The brief lists "CSR sparse flag: default-on" → `C4_CSR_INFERENCE=1`
  default. Confirmed in `batched_pure_neural.py:335` and
  `run_vm.py:358`.
- `C4_5101` / `C4_RELEASE` / `C4_RELEASE_DIR` / `C4_ROOT` / `C4_RUNTIME` /
  `C4_SF_GENERATION` / `C4_SF_RUNTIME` / `C4_GENERATION` / `C4_HEADER` /
  `C4_OPCODES` / `C4_FP_MATH` / `C4_SOFTFLOAT` / `C4_PHASE_DEPRECATION_WARN`
  / `C4_PHASE_STRICT_MODE` appear only inside
  `tools/bundle_autoregressive_quine.py` as quine-bundle string templates
  — they are **not** runtime toggles.
