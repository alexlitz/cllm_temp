## Net interpretation

The smoke gate has recovered to ~88% pass (46/52). The 1096 corpus
has correspondingly cleared every cluster EXCEPT `var_simple_*`,
`var_three_*`, and half of `if_var_*` — all converging on a single
signature attributed to `post_l9_bz_bnz_pc_override` at L34.ffn.

The "gap is real" — the prior fix waves have shifted nearly all the
failure mass onto one op. This is the lowest-cost surface area to
attack: a single op, a single signature, three clusters.

## Recommended next-round target

**Verify the `post_l9_bz_bnz_pc_override` attribution and fix the
+2.55 OUT_LO[0] mass at abs=119 (var_simple).**

Per the memory note's open question: if a static disable of the
192-unit op (e.g. zeroing the layer's contribution at step 0) does
NOT cure var_simple, then the dynamic-verifier carrier-attribution
is wrong and a different op is producing the band-0 mass. The
diagnostic infrastructure should be used to:

1. Ablate `head.bias[MARK_PC]` to -30.0 and re-run var_simple_0;
   if the failure persists, the issue is logit competition rather
   than upstream divergence.
2. Snapshot the per-block residual at `block=35` input vs output for
   var_simple_0; if the +2.55 OUT_LO[0] mass arrives at the input
   (i.e. the residual is already poisoned upstream), the carrier is
   somewhere in L1-L33, not at L34.ffn.
3. Run the `attribute_1096_failure.py` brief on `var_simple_0` and
   compare to the prior 2026-06-04 brief (`.agent-logs/1096_fail_var_simple_0.md`)
   — if the residual-walk pins the same `block=35` op, that's two
   independent signals confirming the attribution.

The 6 surviving smoke failures (LEA + 5 si/li/sc/lc memory tests)
are a distinct cluster from the 1096 surface (no `step0:MEM_addr1
expected=0xff` pin in either; LEA is an addressing test, si/li/sc/lc
are sequential-store tests) — these should be triaged separately.
