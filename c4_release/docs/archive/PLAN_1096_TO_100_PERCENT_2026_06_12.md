Date: 2026-06-12. Owner: this session's campaign. Status anchor: smoke
**46/49** (pytest), 1096 baseline **153/1096** (canonical runner, OOM-proof).

## 0. Framing (read first)

The 1096 corpus is **not 56 independent problems** — it collapses to **6
structural roots**. ~610 of the 943 non-passing programs sit behind just **4
fixable roots (A–D)**; **E** mostly *composes* from A+C; **F** (the diverging
deep clusters, ~233 programs) is a separate, harder, possibly-architectural
wall. So:

- **Achievable target (roots A–E): ~830/1096 (~76%)** — multi-session but
  mechanical, each a diagnosed fix.
- **Stretch / open question (root F): the last ~233** — needs long-horizon
  decode stability the current model may not have.

"Whole 1096 passing" = land A–E (the plan below) **and** crack F (a research
problem with no guaranteed solution in the current architecture).

### Measurement discipline (non-negotiable)
- Iterate per-cluster with `tools/run_1096_canonical.py --ids <range>` (minutes).
- Headline via the full runner (~82 min) or a `--skip-zero-clusters` fast pass
  (~40 min); split across both GPUs to halve it.
- Verify **zero smoke regression** with `python -m pytest tests/test_smoke.py`
  (authoritative) or the **cached** `tools/run_full_smoke.py`. **NEVER** a
  `*_nocache` tool (deleted — it baked a different model and caused a false
  trail; see `project_disk_cache_masks_smoke_regressions`).
- Every fix: declarative DSL, spec_k=0, byte-identity gated
  (`compare_symbolic_to_lowered_*`), no overrides/hooks.

## Phase 1 — Multi-byte arithmetic (root A, ~190 programs)

**The keystone is LANDED** (commit 432cae3a): a multi-byte operand relay
(L13 head → `STACK0_BYTE_VAL_1` slot 602 → the declarative L14 cascade), **no
d_model widening**. sub_16bit passes; sub 1096 3/50→12/50. Remaining work, each
an incremental extension of that pattern:

1. **ADD mirror + no-borrow SUB passthrough** (in flight, a2393aee) → add ~47,
   sub ~38. The `add_rule_for` mirror + an ADD-gated relay + the non-borrow
   minuend-high-byte emit.
2. **MUL width=2 result emit** (in flight, abc287d3) → mul ~50 + mul_overflow
   xfail. Needs the 2-byte *result* to survive the **L15/block-25 + L20/block-30
   result-corruptor** (the d_model wall is gone now). Also fix mul_basic
   (single-byte collapse to 1 — likely the and_basic operand-cleanup mirror).
3. **DIV/MOD multi-byte dividend** → div ~29, mod ~26. A flat lookup is
   256³=16.7M rules (impossible); needs a **bit-serial `multi_pass` cascade**
   (~16 staged FFN blocks + per-bit remainder band) reading the relayed high
   byte. The biggest single sub-task in Phase 1. See
   `DIV_MOD_MULTIBYTE_DIVIDEND_BLOCKER_2026_06_12.md`.
4. **2-nibble PSH-broadcast fix** → values ≥4096 (high byte ≥0x10). Upstream
   `layer10_psh_ax_broadcast` truncates `STACK0_BYTE_VAL` to its low nibble.
   Lower volume (most corpus values <4096) but unblocks the high tail across
   ALL multi-byte ops.

**Exit:** add/sub/mul/div/mod clusters ≥80% pass; smoke mul_basic + mul_overflow
green. **Surface:** l13 (relay), l10 `_l10_carry_propagation_rules` (cascade),
alu_ops/wide_alu_dsl (mul/div), l10 psh_broadcast. **Refs:**
`project_sub16_mul16_var_root_is_l14_borrow_cascade`, `project_mul_div_mod_arch_blocked`.

## Phase 2 — CMP→branch (root B, ~61 programs)

The comparison COMPUTES correctly (gt/lt pass in smoke) but the if-then-else
takes the wrong branch — the CMP-result→BZ/BNZ path is broken in the if
structure. In flight (a28be41d).

- if_gt/if_lt/if_var → fix the comparison-flag→branch relay.
- **if_eq is coupled to the EQ decode-margin** (smoke eq_true/eq_false): the EQ
  engine (commit 25ac173a) computes correct CMP+1/CMP+2 but the OUTPUT_LO[1]-vs-[0]
  decode margin is razor-thin, and eq_false has a 2nd L25 OUTPUT band corruption.
  Fix the EQ decode → if_eq smoke + eq_true/eq_false smoke (knocks out 2 of the
  smoke fails too).
- bool_and → comparison + AND composition (depends on the above).

**Exit:** if_* ≥80%, smoke eq_true/eq_false green. **Surface:** l9 cmp_rules,
l10 cmp_combine, control_flow (BZ/BNZ), the EQ engine. **Refs:**
`project_operand_gather_hybrid_encoding_is_cmp_alu_root`, `WALL4_..._SESSION2/3`.

## Phase 3 — var storage/recall (root C, ~100 programs)

var_simple/mul/three/update are 0/25 each. **One multi-layer fix:** the
var-chain's final link — the block-12 L10-resize CLEAN_EMBED→OUTPUT broadcast
crushes OUTPUT on the var read/store row (the var_simple_12 chain stopped here).
It's CMP-entangled, so **depends on Phase 2** (the CMP path being stable).
4 var fixes already landed this session (l15/l16/l18); this is the last link.

**Exit:** var_* ≥80%. **Surface:** the block-12 L10-resize broadcast head +
the var read/store path. **Refs:** `project_ax_bytes_1_3_ff_leak_root`,
`VAR_SIMPLE_12_LINK5_6_DIAGNOSIS`, the 4 landed var commits.

## Phase 4 — function calls / JSR-LEV (root D, ~150 programs)

func_* (5 clusters × 25) + func_identity, all 0 pass; smoke simple_function
xfail. **The single highest-leverage fix left** (one root → ~150 programs).
Multi-commit:

1. L10 PC byte-passthrough head — **already landed** (cbc22d53).
2. The **L8 operand-state cascade** in the callee: the IMM-in-callee step
   decodes against polluted SP/BP/AX_CARRY frame state → wrong opcode/value.
   The genuine root; needs untangling the stack-frame operand state. Multi-session.
3. L9 `lev_bp_to_pc` relay + L16 lev routing for clean PC restore.
4. Un-xfail simple_function.

**Exit:** func_* ≥70%, simple_function green. **Surface:** l6/l7/l8/l9/l10/l16
(broad — run on a CLEAN tree, after Phases 1-2 free l9/l10). **Refs:**
`project_jsr_simple_function_arch_blocked` (full multi-agent diagnosis),
`PHASE_5_JSR_ENT_LEV_FOLLOWUP.md`.

## Phase 5 — expression evaluation (root E, ~150 programs)

expr_add_mul/paren/mul_div/mod, absdiff, nested_quad/sumsq — multi-operation
expressions. These largely **compose** from A (multi-byte arithmetic) + C (var
storage) + operand-stack sequencing. **Re-measure after Phases 1+3** — many will
already pass. Fix the residual operand-stack-depth / sequencing issues.

**Exit:** expr_*/nested_*/absdiff ≥70%. **Surface:** mostly emergent; residuals
in the operand-gather depth + multi-step PSH/POP.

## Phase 6 — deep recursion/loops (root F, ~233 programs) — THE WALL

loop_*, gcd, rec_* diverge past ~40 steps (skipped by the runner cap). The
neural decode accumulates per-step error over hundreds/thousands of steps
(rec_fib = 8369 steps). **This is the open question, not a mechanical fix:**

- Phases 1-4 *reduce per-step error*, so some SHORTER deep programs may pass
  incidentally — re-measure after A-D with the cap raised.
- The truly-long ones need **long-horizon decode stability**: investigate the
  divergence source (error accumulation? attention saturation on long context?
  position encoding? KV drift?). May require a per-step correction/renormalization
  mechanism or a model recompile — a research effort with **no guaranteed
  solution in the current architecture**.

**Honest exit:** likely partial. Treat ~830/1096 (roots A-E) as the realistic
"done" line; F is a separate stretch program.

## Sequencing & parallelism

```
NOW (in flight):   A(add/sub) ‖ B(if_*) ‖ A(mul)
Next (after wave): A(div/mod bit-serial), A(2-nibble), B(eq decode)
Then:              C(var-link)  [needs B stable]
Then:              D(JSR/LEV)   [clean tree; broad surface]
Then:              E(expr)      [re-measure first — mostly composes]
Finally:           F(deep)      [research; re-measure with raised cap]
```

Roots A and B parallelize (arithmetic ⊥ CMP). C waits on B (CMP-entangled). D
wants a clean tree (broad l6-l16 surface). E is measure-then-mop-up. F is last.
